# 25-poi-radius-selection.md — выбор радиуса для POI категорий

## Контекст

При расчёте POI фичей (количество объектов в радиусе от остановки/точки)
радиус — ключевой параметр. Слишком маленький → пропускаем объекты.
Слишком большой → все маршруты получают одинаковые значения, фича бесполезна.

## Правило (из D-024)

Радиус подбирать **по реальным расстояниям от остановок** до объектов,
а не выбирать «стандартные» 500m/1km.

### CATEGORY_RADIUS_KM (T-168, проверено эмпирически)

| Категория | Радиус | Обоснование |
|---|---|---|
| `school` | 0.5 km | Плотная сеть школ, иначе все маршруты получат n=20+ |
| `clinic` | 0.5 km | Аналогично, поликлиники плотно в жилых районах |
| `park` | 1.0 km | Парки средние, есть крупные (Сокольники, Воробьёвы) |
| `mall` | 1.0 km | ТЦ обычно в центре, 1km покрывает основные |
| `theater` | 1.0 km | Театры в центре, 1km покрывает большинство |
| `culture` | 1.0 km | Музеи+ДК+театры (расширенное) |
| `cinema` | 1.0 km | Кинотеатры распределены по районам |
| `market` | 1.0 km | Рынки локальные, 1km достаточно |
| `train_station` | 1.0 km | Вокзалов мало, но они крупные — 1km от центра |
| `metro_hub` | 1.0 km | Метро = узловые точки, 1km от остановки = walkable |
| `university` | 1.5 km | **Критично**: МГУ ~1.28km от Метро Университет, 1km не хватает |
| `stadium` | 1.5 km | Стадионов мало, нужна бóльшая зона для событий |
| `hospital` | 1.5 km | Больницы крупные, обслуживают большой район |

## Как НЕ надо выбирать радиус

❌ **«Все категории = 500m»** — пропустим крупные объекты (МГУ, стадионы)
❌ **«Все категории = 1km»** — школы/clinics «загрязнят» фичи
❌ **«Фиксированный 2km для всех»** — все маршруты получат n_schools=20+, фича бесполезна
❌ **«Радиус = n_stops маршрута»** — добавляет complexity без обоснования

## Как проверить выбранный радиус

Перед коммитом новых POI фичей запустить sanity-check:

```python
from transit_ai.data.poi_features import count_poi_for_stop, load_stops_catalog
from transit_ai.data.spravochnik_geo import _haversine_km

# Для каждой остановки каждого маршрута — найти расстояние до ближайшего POI категории
catalog = load_poi_catalog()
stops = load_stops_catalog()
for cat in ["university", "stadium", "park", ...]:
    distances = []
    for route_id, route_stops in stops.items():
        for stop in route_stops:
            min_d = min(
                _haversine_km(stop["lat"], stop["lon"], p["lat"], p["lon"])
                for p in catalog if p["category"] == cat
            )
            distances.append(min_d)
    median_d = sorted(distances)[len(distances) // 2]
    print(f"{cat}: median dist = {median_d:.2f}km → рекомендую радиус {max(0.5, median_d * 1.5):.2f}km")
```

**Ожидаемый вывод:**
```
university: median dist = 1.10km → рекомендую радиус 1.50km  ✓
stadium: median dist = 1.20km → рекомендую радиус 1.50km  ✓
park: median dist = 0.65km → рекомендую радиус 1.00km  ✓
```

## Когда пересмотреть радиус

- Добавили **новую категорию POI** (например, `airport`, `railway_station`)
- Существенно **расширили каталог** (>500 объектов)
- На платформе **POI-фичи не дали эффекта** при хорошем holdout → возможно радиус слишком большой (фичи одинаковые для всех маршрутов)
- На платформе **POI-фичи дали отрицательный эффект** → возможно радиус слишком маленький (фичи слишком частые)
