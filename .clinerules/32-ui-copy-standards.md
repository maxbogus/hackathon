# 32-ui-copy-standards.md — Стандарт текстов интерфейса (department-grade)

## Зачем

Заказчик внедряет сервис в Департамент транспорта. Требования к текстам
интерфейса жёстче, чем к прототипу: государственная информационная система
не показывает внутреннюю «кухню» пользователю. Правило зафиксировано после
ревизии копирайта (T-231).

## R1. В UI нет идентификаторов и внутренних кодов

Запрещено выводить пользователю:

- `feature_toggles.name` / `zero_overrides.name` (`use_lag`, `zero_route_5`)
- `feature_set` (`with_all`, `with_poi`, `baseline`)
- `model_id` (`baseline_v1`, `test_submission_baseline`)
- технические флаги (`zeros=ON`), номера тикетов/находок (`T-172`, `F-060`)
- имя БД/таблицы как источник («из БД»)

Разрешено: человекочитаемая подпись из реестра + raw-значение в tooltip
(`title=`) для трассируемости.

Резолвер — `apps/frontend/src/lib/labels.ts`:

| Функция | Назначение |
|---|---|
| `featureName(name, description, t)` | «Учитывать объекты (POI)» (fallback: описание из API → имя) |
| `featureHint(name, t)` | пояснение под подписью (для неизвестных — пусто) |
| `zeroName(name, description, t)` | «Исключить маршрут 5» |
| `zeroHint(name, t)` | пояснение исключения |
| `modelName(modelId, t)` | «Базовая v1»; неизвестные — де-снейкинг «XGBoost v11 base only» |
| `featureSetName(featureSet, t)` | «Все факторы» / «С учётом объектов» / «Базовый набор» |
| `zerosStateText(applied, t)` | «Исключения: вкл.» / «Исключения: выкл.» |

Модуль принимает `Translator` (`t`) параметром — он **pure logic**, без импорта
`t` и без русских литералов (clinerule 20).

## R3. Тон — официальный, директивный, без панибратства

Запрещено: «и езжайте», «свободный вагончик», «погнали», эмодзи-морды,
восклицания, обращения на «ты».

Разрешено: «Выберите маршрут для анализа или перераспределения»,
«Фактическая нагрузка», «Прогнозируемая нагрузка».

Заголовки — существительными: «Перегрузка», «Недогрузка», «Норма», «Нет данных».
Сокращения — только общепринятые, с точкой и заглавной буквой: «чел.»,
«Прогноз: 754 чел.», «Факт. посадки (чел.)».

## R4. Единицы измерения обязательны

Числовые колонки и карточки указывают единицу: «Прогноз (чел.)»,
«Факт. посадки (чел.)», «754 чел.» (ключ `common.unitPeople`).

## R5. Заголовки не обрезаются

Если заголовок таблицы не влезает в колонку (CSS `text-overflow: ellipsis`),
увеличить ширину колонки в `GRID_TEMPLATE_COLUMNS`, а не сокращать слово.
«Маршрут» требует ≥140px (было 70px → на экране «Мар…», затем 110px → всё ещё
резалось при крупном шрифте; T-232: 140px + снятый `ellipsis` у `thStyle`).

Ширины в `GRID_TEMPLATE_COLUMNS` обязаны быть **фиксированными** (`Npx`, `1fr`):
каждый virtualized-ряд — отдельный CSS Grid, поэтому `max-content`/`minmax`
вычислились бы по контенту строки и колонки разъехались бы между header и rows.

## R6. Где живут тексты

- Русские строки — только `apps/frontend/src/lib/i18n/ru-RU.ts` (clinerule 20).
- Компоненты вызывают `t()` / `tf()`; маппинги id → `TKey` — в `lib/labels.ts`.
- Гейт: `make frontend-text-check` (grep кириллицы вне `lib/i18n/`, тестов и
  комментариев).
- Лог миграций — `apps/frontend/src/lib/i18n/MIGRATION.md` (строка на тикет).

## R7. Backend-описания не показываются напрямую

`GET /api/v1/features` отдаёт английские `description` (seed из alembic).
Фронт **не** рендерит их как подписи — только как fallback для тогглов,
которых нет в карте `lib/labels.ts` (тогда видно, что нужна локализация).

## Don't do

- ❌ `{f.name}` / `{z.name}` / `{active.model_id}` напрямую в JSX
- ❌ `{data.feature_set}` / `' · zeros=ON'` конкатенацией
- ❌ Английские слова в подписях («boardings», «WAPE-score», «features»)
- ❌ Разговорный тон и «дружеские» формулировки в диспетчерских экранах
- ❌ Сокращать заголовок вместо расширения колонки
