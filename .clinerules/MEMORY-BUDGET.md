# MEMORY-BUDGET — Анти-краш для AI-агентов

> **КРИТИЧНО.** Лимит контекста LLM ~192K токенов. System prompt уже занимает ~20K.
> **Бюджет на работу: ~170K токенов.**
> Превышение = context overflow → потеря качества → крэш сессии.

## Бюджет по слоям

| Слой | Лимит | Что внутри |
|---|---|---|
| System prompt + clinerules | ~25K | AGENTS.md (0.4K), .clinerules/* (читать выборочно!), навыки |
| Tool definitions | ~10K | описание доступных тулов |
| История чата | ~30K | предыдущие ответы и tool calls |
| Файлы в контексте | ~95K | то, что агент прочитал через read_file |
| Генерация ответа | ~10K | будущий ответ |
| **Резерв на ошибки** | **~20K** | на случай если что-то пойдёт не так |

## Что НЕЛЬЗЯ делать

### ❌ read_file на большие файлы
- JSON > 1MB (история чата, большие дампы, логи)
- yarn.lock, uv.lock (бесполезно — не наша семантика)
- .csv/parquet > 10MB (используй polars/pandas с фильтрами)
- сгенерированные `apps/frontend/src/generated/api.ts` (там тысячи строк)

### ❌ Читать все clinerules сразу
В `.clinerules/` 16 файлов. Каждый по 200-400 строк = 5-10K токенов.
Вместо этого:
1. Прочитай `00-AGENTS.md` (этот файл)
2. По названию выбери нужный (1-2 файла)
3. Для длинных инструкций (RED→GREEN) используй `use_skill` (загружается on-demand)

### ❌ Дублировать текст в чате
Если что-то уже есть в файле — **сошли** на файл, не копируй в ответ.

## Что ДЕЛАТЬ

### ✅ execute_command для больших файлов
```bash
# Вместо read_file на 100MB JSON
python3 -c "import json; d=json.load(open('big.json')); print(d.keys())"
head -100 data/big.json
grep -c "passenger" data/big.json
```

### ✅ use_skill для длинных процедур
```python
# Плохо: читать .clinerules/16-tdd-cycle.md целиком в контекст
# Хорошо: invoke skill("16-tdd-cycle") — загрузится по требованию
```

### ✅ Промежуточные результаты → в файлы
```python
# Вместо print(big_dataframe)
df.head(100).to_csv('/tmp/preview.csv')
# Потом: tail -50 /tmp/preview.csv
```

### ✅ Разделяй задачи на сессии
Если задача длинная (>10 tool calls) — закончи сессию на логической границе:
1. Запусти `make handoff-update`
2. Проверь что HANDOFF.md обновился
3. Начни новую сессию с упоминания HANDOFF.md

## Мониторинг

Если ответ агента становится:
- Медленным (>30s на tool call) — контекст перегружен
- Повторяющимся (тот же вопрос дважды) — потерял нить
- Слишком коротким без причины — исчерпал лимит

**Действие:** закончи сессию, обнови HANDOFF.md, начни новую.

## Emergency: контекст на исходе

```bash
# 1. Обнови HANDOFF (источник истины)
make handoff-update

# 2. Закоммить всё что есть
git add -A && git commit -m "wip(handoff): save progress before context overflow"

# 3. Начни новую сессию с фразы:
"Продолжай с HANDOFF.md — контекст переполнился в прошлой сессии."
```
