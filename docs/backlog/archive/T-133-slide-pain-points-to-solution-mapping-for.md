# T-133: слайд «Боли пассажиров → наше решение» для очной презентации жюри

## Context

Бенефициары хакатона: Департамент транспорта Москвы, диспетчеры, пассажиры.
Главная цель хакатона (Ликсутов): «повышение качества и безопасности поездок миллионов пассажиров».

Жюри оценивает customer-centric подход, а не ML-метрики. Слайд, который явно мэппит
боли → решение — **сильнейший сигнал**, что мы понимаем заказчика.

## Acceptance Criteria

- [x] Создан файл `docs/hackathon/presentation/slide_01_pain_points.md`
- [x] 5 конкретных болей пассажиров (из `docs/hackathon/user_stories.md`):
  1. «Когда приедет трамвай?» (непредсказуемость интервалов)
  2. «Будет ли место?» (переполненность)
  3. «Ехать сейчас или подождать?» (отсутствие информации)
  4. «Почему интервал 20 минут?» (нет прозрачности для диспетчера)
  5. «Новые линии помогут?» (нет симуляции сценариев для города)
- [x] Каждая боль → конкретное решение (ссылка на тикет)

## Technical Notes

Структура слайда (markdown, рендерится через `marp` или `pandoc` в PDF/PPT):

```markdown
# Боли пассажиров московского трамвая

> «20 минут ожидания = 78 000 человеко-часов потерь ежедневно»

## 5 болей → 5 решений

| Боль пассажира | Наше решение | Тикет |
|---|---|---|
| «Когда приедет трамвай?» | Прогноз ETA для следующих 3 рейсов | T-127 |
| «Будет ли место?» | Прогноз загрузки каждого рейса в % | T-128 |
| «Ехать или подождать?» | Рекомендация на UI («Садитесь» / «Подождите N мин») | T-130 |
| «Почему интервал 20 мин?» | Диспетчер видит прогноз перегрузки заранее | T-131 |
| «Новые линии помогут?» | Monte Carlo симуляция Т2 | T-036 |

## Бенефициары

- **Департамент транспорта Москвы** — инструмент управления сетью
- **Диспетчеры** — раннее предупреждение перегрузок
- **Пассажиры** — предсказуемость, сокращение ожидания на 15%
```
